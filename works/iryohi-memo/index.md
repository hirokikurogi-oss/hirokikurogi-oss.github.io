# 医療費と交通費のメモ

家族の医療費と通院の交通費を記録して、確定申告の医療費控除で使う国税庁の「医療費集計フォーム」（Excel）の形で書き出す iOS アプリ。Flutter 製。企画・設計・実装から App Store への申請までを個人で担当しています。

---

## 何を解決するアプリか

医療費控除の明細は、マイナポータルの連携で取り込めるものがあります。一方で、通院の交通費、市販薬、接骨院、自費の診療、年末に払った分は取り込めません。こうした分は、紙の領収書を年明けにまとめて集計することになりがちです。

このアプリは、通院のたびに病院代と交通費を一緒に記録しておき、年が明けたら**国税庁の集計フォームの形で書き出す**ためのものです。国税庁が作ったアプリではなく、国税庁が公開している集計フォームのファイルを同梱し、入力値を書き込んで出力しています。領収書を撮ると、金額・支払先・支払日を端末内で読み取って入力欄に入れます。書き出しは無料で、広告もアカウント登録もありません。

## 主な機能

- **病院代と交通費を1回で入力** — 人・支払先・区分・金額を選んで入れる。交通費は片道か往復を選べて、前回の金額が入る。「保存して次へ」で、日付と人・支払先を引き継いで連続で入れられる
- **領収書の読み取り** — 写真から金額・支払先・支払日を読み取って入力欄に入れる。区分は、登録済みの支払先ならその既定の区分、そうでなければ支払先の名前から推測する。読み取りは端末内で完結する。結果は下書きで、保存の前に確認できる
- **年の合計と内訳** — 支払額から補填額を引いた合計を、人別・区分別に表示する。10万円（総所得金額等が200万円未満の人は、その5%）の目安までの残りも出すが、控除額の計算はしない
- **集計フォームへの書き出し** — 国税庁の医療費集計フォーム（Ver.3.1）に書き込んだ .xlsx を作る。確定申告書等作成コーナーで読み込める
- **Pro（買い切り）** — 同じ人・支払先・区分を1行にまとめた書き出し、領収書の写真つき PDF 明細、複数年をまとめた PDF
- **バックアップ** — 写真つきの zip を書き出し、機種変更のときに復元できる（無料）

## 設計上の判断

### 1. サーバーを持たず、端末内で完結させる

人・支払先・記録は端末内の SQLite に、領収書の写真はアプリ内のファイルに保存します。アカウント登録もサーバーも解析 SDK も持たず、App Store のプライバシー情報は「データ収集なし」です。

医療費の記録は、家族の通院先や病名の手がかりが並ぶ、個人的なデータです。預かる設計にしなければ、サーバーからの漏えいを心配することも、運用コストもありません。領収書の文字認識も、通信のない Vision で行います。アプリが記録を送り出すのは、利用者が .xlsx・PDF・zip を自分の手で送ったときだけです（購入のときの App Store との通信は除きます）。

### 2. 集計フォームは、公式の .xlsx を直接書き換えて作る

Excel を扱う定番のパッケージで読み書きすると、国税庁のファイルにある入力規則・書式・シート保護が落ちやすく、作成コーナーで読み込めなくなるおそれがあります。そこで、公式の .xlsx をアプリに同梱し、zip のまま展開して、書き換えるのは次の2か所だけにしました。他のファイルには触れません。

- `sheet1.xml` の B〜J 列のセル（人・支払先・区分・金額・補填額・支払年月日）
- `workbook.xml` の `calcPr`。合計欄の式を、開いたときに再計算させる指定を足す

式のセルは触りません。支払年月日は Excel のシリアル値（1899-12-30 からの日数）で書きます。テストでは、書き出した .xlsx の `sheet1.xml` からセルを読み戻して、値と区分が入力と一致すること、入力規則とシート保護が書き込み前後で変わらないことを確認しています。

国税庁のコンテンツは、公共データ利用規約に沿って同梱しています。設定画面には出典と、入力値を書き込んで出力していることを書いています。

### 3. フォームの制約を、入力と書き出しの両方で守る

集計フォームには、人は全角10文字、支払先は全角20文字、金額は 0〜999,999,999、1ファイル995行までという制約があります。書き出したあとで作成コーナーに弾かれると、利用者はどこを直すのか分かりません。

そこで、人と支払先の名前は**全角に変換した後の文字数**で数えます。半角英数記号・半角スペース・半角カナを全角にし、半角カナの濁点は直前の文字と結合します（「ﾀﾞ」→「ダ」）。入力欄の段階で止め、書き出しの前にも、超えている人と支払先を一覧にして出します。995行を超えるときは、黙って切り捨てず、995行ごとに複数のファイルへ分けます。

### 4. 合計と補填、年の決め方を、画面に書いたとおりに実装する

合計は「支払額 − 補填額」です。補填額はその記録の金額を上限にして引き、余っても他の記録からは引きません。補填額が金額を超える入力は、入力欄で止めます。合計がマイナスにならないことは、集計のテストで確認しています。

年は**支払日**で決めます（受診日の項目はありません）。12月に受診して、1月に払った分は、1月の支払として翌年に入ります。マイナポータルから取り込む分は、記録ごとの印で区別します。この印がある記録は、合計には含め、書き出しからは外します。二重に計上しないためです。控除額・還付額は、計算も表示もしません。

### 5. 交通費は別の記録として、元の通院に紐づける

交通費は、通院の記録とは別のレコードにして、親の記録の ID を持たせます。集計フォームでは「その他の医療費」の別の行になり、支払先は交通機関の名前になるためです。画面では通院の下にまとめて見え、親を消すと子の交通費も一緒に消えます。

最終レビューでは、通院の記録に「マイナポータルで取り込む分」の印を付けると、**取り込めないはずの交通費まで書き出しから消える**不具合が見つかりました。交通費の記録にはこの印を引き継がない形に直しています。自家用車のガソリン代・駐車場代は対象外である旨を入力欄に常時出し、タクシーを選んで保存しようとしたときは、対象外になりやすい旨の確認のダイアログを出します。

### 6. 領収書の読み取りは、純粋なパーサーと、下書きだけを埋める画面に分ける

Vision から受け取るのは、文字の行と、画像の中での位置です。ここから金額・支払先・支払日・区分を取り出す処理は、Swift 側ではなく Dart の**純粋な関数**にして、実機がなくてもテストできるようにしました（31ケース）。

- 行は縦位置で同じ行にまとめ直し、左から右に結合する
- 金額は、「合計」「領収金額」「請求額」などの行を優先する。「お預り」「お釣り」「ポイント」「小計」「税」を含む行は除く（「税込」は合計の修飾語なので除かない）。ラベルがなければ、最大の数字を取る
- 数字の取り違えを避けるため、金額を探す前に、日付・時刻・電話番号・郵便番号を消す
- 支払日は、西暦・和暦（令和、R7.11.11 など）・月日だけの形に対応し、2/30 のような存在しない日付は捨てる
- 支払先は、上から5行以内で、日付・電話番号・住所・見出し・数字だけの行を飛ばした最初の行。登録済みの支払先の名前を含む行があれば、最長一致でそちらに決める

画面側の決まりは次のとおりです。

- 読み取りの結果は、利用者が手で決めていない欄にだけ入れる。手で決めた欄は上書きしない。入った欄は色で示し、保存前に確認するよう促す
- 読み取りは非同期なので、世代番号を持たせる。画面を閉じた・保存した・次の読み取りを始めたあとに返った古い結果は捨てる
- 読み取りが失敗しても、写真の保存は止めない
- 「保存して次へ」で引き継いだ値は、次の読み取りで置き換えてよい扱いにする

### 7. 無料と Pro の線引きは、書き出しを無料のままにして決める

記録・合計・写真・バックアップ・集計フォームの書き出しは無料で、回数の制限もありません。Pro（買い切り¥500）で使えるのは、まとめ書き出し、写真つき PDF、複数年の PDF です。「1年記録したのに、申告の直前に書き出せない」という状況を作らないため、書き出し自体は課金の対象にしていません。

購入の状態は端末に保存し、オフラインでも次の起動で Pro のままになります。起動時に自動で購入の復元はしません（Apple ID のサインインを求められることがあるため）。復元は、設定画面と購入画面のボタンから行います。

### 8. バックアップの復元は、検査してから、途中で失敗しても今の写真が消えない順で置き換える

医療費の記録は、機種変更で消えると困ります。バックアップは無料にし、復元は、zip を検査してから書く手順にしました。次のものは、書き込む前に断ります。

- ファイル名に `..` や絶対パスがあるもの
- zip に記載された展開後サイズの合計が、上限（2GB）を超えるもの
- manifest の版数が新しすぎるもの、別のアプリのバックアップ
- 写真の SHA-256 が合わないもの
- 記録・人・支払先・写真の ID が重複しているもの、存在しない行を指しているもの

パス・サイズ・版数・SHA-256 の検査と写真の展開は、別の Isolate で行います。ID の重複と参照の検査は、展開のあとに行います。

復元は今のデータをすべて置き換えるので、端末にデータがあるときは確認を出します。置き換えの順番は、①写真を新しいフォルダに先に用意する（失敗しても DB と今の写真は無傷）、②DB を1つのトランザクションで置き換える（失敗したら元のまま）、③写真のフォルダを入れ替える、です。③で失敗したときは、今の写真を元の場所に戻します。ただしこの時点で DB の行はバックアップの内容に置き換わっているので、その旨を画面に出して、もう一度の復元を促します。

### 9. PDF は1冊ずつ作り、写真の数で分ける

写真つき PDF は、年ごとの章に分けて、1ページに2件分の枠を並べます。写真が多い記録は、続きの枠に回します。生成は画面を止めないよう別の Isolate で行い、渡す画像は縮小済みの JPEG のバイト列だけにして、展開した画素を持ちません。写真が150枚を超えるときは、記録の区切りで複数のファイルに分け、1冊ずつ作っては手放します。写真が消えていたり壊れていたりしても PDF の生成は止めず、代わりの文言を出します。

## テスト方針

集計フォームの書き出し、入力の制約、読み取りの解析のように、間違えると申告に響く部分を優先してテストしています。全体で237件です（v1.0.0 時点）。テストが確かめるのはファイルの構造と値が意図どおりかどうかで、作成コーナーでの読み込みは、実際に書き出したファイルで確認しています。

- `shuukei_form_writer_test.dart` — 書き出した .xlsx を XML として読み戻し、セルの値・区分が入力と一致すること、入力規則とシート保護が書き込み前後で同一なこと、995行と996行の境目（7ケース）
- `export_builder_test.dart` — 1件ずつ・まとめるの両方の行の作り方、マイナポータル分の除外、補填額の上限、995行ごとの分割（9ケース）
- `validation_test.dart` — 全角変換後の文字数、半角カナの濁点、金額と補填額の範囲（8ケース）
- `receipt_parser_test.dart` — 金額のラベルと除外語、日付の各形式、支払先の選び方、区分の推測（31ケース）
- `record_edit_ocr_test.dart` — 読み取りが空の欄にだけ入ること、古い結果を捨てること、失敗しても写真の保存が止まらないこと（23ケース）
- `backup_service_test.dart` — `../` を含むパスの拒否、サイズ上限、参照の検査、入れ替えに失敗したとき今の写真が元の場所に戻ること（18ケース）
- `receipt_pdf_service_test.dart` — ページ割り、写真数での分割、写真が欠けた記録（11ケース）
- `entitlement_service_test.dart` — 購入・復元・キャンセル・失敗（10ケース）

カメラロール・共有・購入・ファイル選択・文字認識は窓口の抽象クラスを挟み、テストでは偽物に差し替えています。
